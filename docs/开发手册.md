# MinoWorkbench 开发手册

> 状态：**待审阅**（v4）
> 配套：`合并迁移方案.md`（步骤与工期）、`页面与组件清单.md`（逐页处置）。本手册定规则。

## 1. 这个项目是什么

MinoWorkbench 是 **MinoStudio + MinoConsole 合并后的唯一前端**，纯 Web，不含 Electron。

| 产品 | 定位 | 本次变化 |
|---|---|---|
| **MinoWorkbench** | 唯一前端：测试工作台 + 管理后台 | 新建，React |
| MinoNexus | API / LLM / DB | 不变。客户端只跟它说话 |
| MinoScout | 设备执行器，拨号 Nexus `/node` | 不变。不再由前端安装 |
| ~~MinoStudio~~ | 桌面测试工作台 | Workbench 稳定后归档 |
| ~~MinoConsole~~ | Web 管理后台 | Workbench 稳定后归档 |

## 2. 这不是代码迁移，是重建

**本项目不把 Vue 代码逐行翻译成 React。**

做法是：**沿用现有页面的业务思路，重新设计交互，用 React 实现。** 现有 Vue 代码的角色是**需求说明书**——从里面抽出"这个页面要做什么、有哪些状态和边界情况"，然后重新设计怎么做得更好。

三条推论，每条都会影响你每天的判断：

1. **原实现怎么写的不构成任何约束。** 原来 2,000 行的单体面板、手写的 loading 开关、靠 `nextTick` 对齐的滚动位置，都不要带过来。
2. **但原有的业务行为是硬约束。** 不能因为重新设计就丢功能。每个页面开工前必须先写**行为契约**（§3），它既是设计输入，也是验收依据。
3. **工期按"设计 + 实现"两段算，不按代码行数折算。** 代码行数只用来判断复杂度量级，不用来估工时。

> 现有代码里的 Vue 写法仍需读懂，所以 §6 保留了一份 Vue→React 对照表。**那是用来读原代码的，不是用来翻译的。**

## 3. 行为契约：每个页面的开工前置

重建最大的风险是**漏功能**——重新设计时很容易把藏在 2,000 行里的某个边界分支丢掉。唯一有效的防范是开工前先把行为列清楚。

每个页面（或面板）开工前，在 `docs/contracts/<页面名>.md` 写一份，内容只要五节：

```markdown
## 数据
来源哪些 Nexus 接口、哪些 WebSocket 推送、刷新/轮询策略

## 状态
页面有哪些状态；哪些挂 URL（可分享/可刷新恢复）、哪些是临时态

## 交互
用户能做哪些操作；每个操作的前置条件、成功后的反馈、失败后的反馈

## 边界
空态、加载态、无权限、接口超时、并发冲突、长列表、超长文本

## 不做
明确砍掉的原有行为（及原因）
```

规则：

- **契约从现有代码里抽，不靠记忆。** 读原 `.vue` 文件，把 `v-if` 分支、`watch` 触发、错误处理逐条落到"边界"节。这是读原代码的唯一目的。
- 契约**先过评审再做设计**，设计稿和实现都以它为准。
- 验收按契约逐条走，**不做新旧页面的代码行数或像素对比**。
- 契约里的"不做"节是明确授权，写下来才算砍掉；没写的不许少。

## 4. 铁律

1. **只跟 Nexus 说话。** 不直连 Scout、不直连数据库、不直连第三方 API。
2. **Nexus origin 来自 `VITE_NEXUS_URL`**，默认 `http://mino.local:10104`。Nexus 启动时自己注册这个域名。**不做 IP 选择器**，不写死 IP，不做"探测可用地址"。
3. **不启停其他产品。** 代码里不出现对 Nexus / Scout 进程的 start / stop / kill。
4. **禁止出现旧品牌名**（任何大小写拼写）。具体禁用词见主仓库 `CLAUDE.md`，CI 从 `scripts/banned-words.txt` 读取后扫描，**该词本身不写进任何源码与文档**——包括这条规则。
5. **不引入任何 Electron 相关依赖。** 没有 `window.electronAPI`，没有 preload，没有 IPC。
6. **没有行为契约不许开工。** 见 §3。
7. **单文件超 400 行要在 PR 里说明理由，超 800 行不许合并。** 见 §10。

## 6. 读懂原 Vue 代码的对照表

**用途：读原代码抽行为契约。不是翻译清单。**

实测原仓库用量：`ref(` 784 ・`computed(` 603 ・`watch(` 133 ・`v-model` 338 ・作用域插槽 212 ・`provide/inject` **0**。

| Vue 写法 | 含义 | 新代码里对应什么 |
|---|---|---|
| `ref(x)` / `.value` | 可变状态 | `useState`；读写都没有 `.value` |
| `computed(() => …)` | 派生值 | 直接在渲染里算。**默认不包 `useMemo`**，只有实测昂贵才包 |
| `watch(a, cb)` | a 变了做副作用 | 先判断它在做什么：**取数据 → TanStack Query**；同步 DOM → `useEffect`。注意 Vue `watch` 默认不立即执行，`useEffect` 挂载时会执行一次 |
| `reactive({})` | 可变对象 | `useState(obj)` + 整体替换 |
| `v-model="x"` | 双向绑定 | `value` + `onChange`。**antd 的 `onChange` 签名不统一**：`Input` 给 event，`Select`/`Switch`/`DatePicker` 给值 |
| `defineProps` / `defineEmits` | 入参 / 出事件 | 函数参数 + `interface`；事件用 `onXxx` 回调 |
| `defineExpose` + 父 `ref` | 父调子方法（5 处） | **优先改成状态上提**，实在拆不动才 `useImperativeHandle` |
| 具名 / 作用域插槽（212 处） | 父决定子的某块渲染 | 多数是 `el-table-column` 的 `#default="{row}"` → antd `columns[].render`；其余用 `ReactNode` prop |
| `nextTick`（39 处） | 等 DOM 更新 | `useLayoutEffect`。**多数是在手工对齐滚动位置，重新设计时应该消掉，而不是照搬** |
| `<Teleport>` / `<Transition>` | 传送 / 过渡 | antd 的 Modal/Drawer 自带 portal；过渡用 CSS |
| `onMounted` / `onUnmounted` | 生命周期 | `useEffect(() => {…; return cleanup}, [])`。WebSocket / 定时器 / 监听必须返回 cleanup |
| `route.query` | URL 状态 | `useSearchParams`。**原仓库大量用 `?tab=&board=&view=`，这是好设计，保留并规范化** |

### 原代码里这些模式一律不要带过来

| 原模式 | 为什么不要 | 换成 |
|---|---|---|
| `ref(loading)` + `watch(id, fetch)` + `try/catch` | 竞态、重复请求、每页一套写法 | TanStack Query（§8） |
| 手写 `setInterval` 轮询 | 卸载泄漏、无退避 | `refetchInterval` |
| 组件内维护一份服务端数据的镜像 | 两份真相 | `queryClient.setQueryData` |
| 2,000 行单体面板 | 没法读、没法改、没法测 | 按 §10 拆 |
| `nextTick` 对齐滚动 | 脆弱，窗口一变就错位 | 重新设计布局，让它不需要对齐 |

## 7. 交互设计方向

要求是"更高级、更有交互"。下面六条不是凭空提的，每条都对应现有代码里的一处实证短板。做设计时按这些方向走；偏离要在契约里说明。

### 7.1 表格

**证据**：原仓库 402 处 `el-table-column`，是重度表格应用；`el-table` 无虚拟滚动；没有列配置持久化；行内编辑每页一套写法。

- 长列表上 **TanStack Virtual** 虚拟滚动，不再靠分页回避性能问题。
- **列配置持久化**：列宽、显隐、顺序存起来（每视图一份），刷新后还在。
- **行内编辑统一一套范式**：进入/保存/取消/校验失败的表现一致。
- 批量操作用 `rowSelection` + **浮动操作条**，不再在每行堆按钮。
- 分页、排序、筛选**全部走服务端 + TanStack Query**，key 里带上筛选条件。

### 7.2 执行时间线（核心页面，重点重做）

**证据**：`ExecutionTimeline.vue` 2,196 行，把时间轴、步骤详情、截图对比、事件列表全塞在一个文件里；`ExecutionStepDetailDrawer` 另有 951 行。

- 拆分。读完代码后确认有 **7 块独立职责**（判定头 / 步骤轨道 / 瀑布图 / 截图胶片条 / 详情抽屉 / 截图对比器 / 运行树）+ 1 个数据层 hook，拆法见 `contracts/execution-timeline.md`。
- **当前选中步骤改挂 URL**。原实现放在组件内，刷新丢失，也没法把"第 7 步失败"的链接发给同事。
- 实时追加时，**用户手动上滚后停止自动跟随**。原实现无条件滚到底，正在看前面的步骤会被强行拽走。
- 加**失败步骤快速跳转**（直接跳到第一个失败步骤）。
- 加**步骤类型筛选**和**时间轴缩放**。
- 截图对比做成前后并排 + 差异高亮，而不是两张图平铺。

### 7.3 信息架构

**证据**：`AppShell.vue` 2,387 行，撑着 11 个 tab + 每个 tab 下的二级 board，两层平铺导航。裁剪后剩 7 个 tab。

- 改成**主工作区 + 可收起的上下文侧栏**，替掉"tab + 二级 board"两层平铺。
- tab 切换**不丢状态**（已选行、滚动位置、筛选条件）。
- 视图状态继续挂 URL，保持"甩链接给同事"这个真实用法。

### 7.4 加载与反馈

**证据**：`el-skeleton` 全库只用了 1 处，加载态不统一；错误处理散落在各页的 `try/catch` 里。

- **统一骨架屏**，首屏不出现布局跳动。
- 写操作用 TanStack Query 的**乐观更新**，失败自动回滚并提示。
- 页面级 **错误边界**，一个面板炸了不整页白屏。

### 7.5 可读性与密度

**证据**：工作区里有未提交的 `styles/studio-readability.css` 和对 `work-shell.css` 的改动——说明字号、行高、对比度被反复手工调过。

- 建立 **token 体系**（字号、行高、间距、对比度），把那些手工调整固化成 token，而不是再写一个覆盖文件。
- 提供**紧凑 / 舒适两档密度切换**。数据密集的表格页和阅读型的详情页需要的密度不一样。

### 7.6 效率

**证据**：原有 `CommandPalette.vue` 142 行（待确认是否在用），说明有这个需求但做得浅。

- **命令面板（⌘K）**：跳页面、跳应用、搜用例、触发常用操作。
- 列表和表格支持**键盘导航**。
- 常用操作给快捷键，并在 UI 上标出来。

## 8. 服务端状态约定

```ts
// api/ 层：纯函数，不含 React
export const fetchAppList = () => request.get<App[]>('/api/apps').then(r => r.data)

// domains/*/queries.ts：key 和 hook 放一起
export const appKeys = {
  all: ['apps'] as const,
  detail: (id: string) => ['apps', id] as const,
  list: (filters: ListFilters) => ['apps', 'list', filters] as const,
}
export const useAppList = () => useQuery({ queryKey: appKeys.all, queryFn: fetchAppList })
```

- **query key 必须集中声明**在 `domains/*/queries.ts` 的 `xxxKeys` 里，不在组件里拼数组——否则失效时找不全。
- 服务端分页/排序/筛选的参数**进 query key**，这样切筛选条件自动走缓存。
- 写操作用 `useMutation` + `invalidateQueries`，不手动 `setState` 同步列表。
- 轮询用 `refetchInterval`，不自己写 `setInterval`。
- WebSocket 推送（`mWebSocket` / `wsAppGraph` / `managementWebSocket`）收到消息后调 `setQueryData` 或 `invalidateQueries`，**不维护组件内镜像状态**。
- 全局默认：`staleTime: 30_000`、`retry: 1`、`refetchOnWindowFocus: false`。

## 9. 目录结构与路由

```
src/
  api/              # 按 Nexus 资源分文件，纯函数，不含 React
  components/       # 跨域复用组件
  domains/
    testing/        # 测试工作台
    admin/          # 管理后台
  hooks/
  layouts/          # WorkShell / AdminLayout
  lib/              # request、auth、权限、工具
  router/
  styles/           # tokens.css 在这
  types/            # Nexus 返回体类型
  ui/               # antd 二次封装层
```

**domains 优先于按类型分目录。** 一个页面的 view / 子组件 / hook / 类型 / 契约放一起。

### 路由

- `createBrowserRouter`，**真实 URL，不用 hash**。原 Studio 用 hash 纯粹是 Electron 的 `file://` 限制。部署侧配好 history fallback。
- **两套导航独立，原 URL 全部保留，不加前缀。** 两边根路径实测零冲突，现有书签和分享链接继续有效。

| 导航 | 布局 | 入口 | 权限 |
|---|---|---|---|
| Studio 工作台 | `WorkShell` | `/testing` | 登录即可 |
| Console 管理 | `AdminLayout` | `/dashboard` | 需 admin 角色 |

- `/settings/**` 归 Studio；Console 原有 `/settings → /dashboard` 重定向保留。
- 权限收在一处：`router/guards.tsx` 的 `<RequireAuth>` / `<RequireRole role="admin">`。原两个项目各写了一份 `beforeEach` 且逻辑不一致，只留一份。
- 旧 URL 重定向逐条搬（两边合计 40+ 条）。不加前缀，这步只是平移。

## 10. 规模红线

原仓库最大的几个文件：`PageDetailEditor.vue` 3,081（已砍）、`QaProcessPanel.vue` 2,995（已砍）、`AppShell.vue` 2,387、`ExecutionTimeline.vue` 2,196。**裁剪后 `ExecutionTimeline` 和 `AppShell` 是最大的两个，都在重做范围内。**

- 单文件 **> 400 行**：PR 里说明理由。
- 单文件 **> 800 行**：不许合并，先拆。
- 拆的方向：JSX 按区域拆子组件、逻辑按关注点拆 hook、表格 `columns` 单独成文件、常量和类型外移。
- 因为是重建而非翻译，**没有"先照搬以后再拆"这个选项**。

## 11. 样式约定

- 布局（flex / grid / 间距 / 响应式）用 Tailwind。
- 组件内部复杂样式用 `*.module.css`，与组件同名。
- 颜色、间距、圆角、字号**只允许引用 token**，定义在 `styles/tokens.css`，同时注入 antd 的 `ConfigProvider theme`。不许写字面量色值。
- 深浅色：`:root` 定义浅色全集，`@media (prefers-color-scheme: dark)` 和 `[data-theme="dark"]` 各覆盖一遍 token。
- **不要在业务代码里直接 import antd。** 在 `src/ui/` 做薄封装，业务只 import `@/ui`。封装层只做"收默认值 + 统一签名"，不做功能增强。

## 12. 命名与提交

- 组件 `PascalCase.tsx`，hook `useXxx.ts`，纯函数模块 `camelCase.ts`。
- 类型放 `types/`，按 Nexus 资源分文件，字段名跟后端一致，**不在前端改名**。
- 分支 `feat/` `fix/` `chore/`。重建类 PR 用 `rebuild/` 前缀，标题带页面名：`rebuild: 执行时间线`。
- 提交信息用中文，一句话说清改了什么。

### CI 必须卡的三条

1. `npm run typecheck` 通过
2. 禁用词扫描为空（`scripts/check-banned-words.sh`）
3. `grep -rn "electron" src package.json` 为空
