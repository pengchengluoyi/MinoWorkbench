## 0. 这一版改变了方案的性质

v1–v3 是**代码迁移**方案：按"Vue 行数 × 转换速率"估工期，目标是功能等价。

**v4 是重建方案**：沿用现有页面的业务思路，**重新设计交互**，用 React 实现。现有 Vue 代码降级为**需求说明书**——从里面抽行为契约，然后重新设计怎么做得更好。

| | v3 迁移 | **v4 重建** |
|---|---|---|
| 现有代码的角色 | 翻译原文 | 需求说明书 |
| 工期估算单位 | 代码行数 | 页面数 × （契约 + 设计 + 实现） |
| 验收方式 | 功能等价 | 按行为契约逐条验收 |
| 原实现的约束力 | 高（照搬结构） | **零**（只约束业务行为） |
| 单人工期 | 16 周 | **20.5 周** |

**重建比翻译贵约 4.5 周**，多出来的是行为契约、交互设计和评审。换到的是：不用背 2,000 行祖传实现，可以直接用 antd 成品 + TanStack Query 把手写代码大幅压缩，以及开发手册 §7 那六项交互升级。

## 4. Electron 下线与 Scout 改造

实测只有 11 个文件引用 `electronAPI`，集中在 `ScoutNodesPage.vue`（14 处）、`ScoutInstallPanel.vue`（10 处，已死）、`UpdatePrompt.vue`（6 处）。

### 4.1 直接平替

`openExternal` → `window.open` ・`selectFile` → `<input type="file">` ・窗口控制 → 浏览器原生（连带删自绘标题栏）・自动更新 → 删 ・`hostPlatform` → `navigator.platform`（仅 1 处）・`getRuntimeStatus` → Nexus HTTP

### 4.2 Scout：保留项

| 能力 | 通道 |
|---|---|
| 停止 / 重启 | Nexus 经 `/node` 长连接下发命令，Scout 自行执行 |
| 查看日志 | Scout 上报日志尾部 → Nexus → 前端；页面内查看器 + 下载，替代"打开日志文件夹" |
| 升级 | Nexus 下发目标版本，Scout 自己拉包重启；前端只提供触发按钮 |
| 配置 | 配置存 Nexus，Scout 启动时拉取；前端改的是 Nexus 上的配置 |

### 4.3 Scout：做不到的项

**冷启动（Scout 未运行时拉起）做不到。** 进程没在跑 → `/node` 连接不存在 → 没有接收方。浏览器无法在远端机器上拉起进程，这是安全模型的硬限制，换任何前端框架都一样。

**解法**：设备侧装成常驻服务（launchd / systemd / Windows 服务，开机自启 + 崩溃自拉），前端"启动"按钮的实际语义变成"唤醒 / 重启"。

安装 Scout、打开日志文件夹、设备投屏（死代码，不恢复）、页面录制器（Electron webview 注入，Web 无法实现）同样下线。

### 4.4 跨产品依赖（阻塞节点页写功能）

| 产品 | 需新增 |
|---|---|
| **Nexus** | `/node` 下行命令通道（`stop`/`restart`/`upgrade`）、日志拉取接口、Scout 配置存取接口、`getRuntimeStatus` 原有字段的 HTTP 版 |
| **Scout** | 接收并执行下行命令、上报日志尾部、支持自更新、**安装为设备侧常驻服务** |

> 本仓库不改这两个产品，也不启停它们。**接口未就绪前，`ScoutNodesPage` 先做只读看板，写操作留占位。**

### 4.5 顺带清掉一处架构违规

`CLAUDE.md` 写明 **"MinoScout — device executor. Dials Nexus `/node`. Not spawned by Studio."**，但 preload 里有 `scoutStart`/`scoutStop`/`scoutInstall`/`scoutDownload` 整套本机 IPC。去 Electron 后统一走 Nexus，实现与架构约定对齐。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **重新设计时漏功能** | 重建模式的头号风险，比翻译模式高得多——藏在 2,000 行里的边界分支最容易丢 | 行为契约（手册 §3）是唯一有效防线：开工前从原代码逐条抽 `v-if` 分支、`watch` 触发、错误处理；验收按契约走 |
| **零测试** | 回归只能手测 | 阶段 6 留足 2 周，同期补 8–12 条 Playwright 冒烟 |
| **设计返工** | 交互方案评审反复，拖慢节奏 | 阶段 0 就把 token、表格范式、两档密度定死；后续页面在既定范式内设计，不逐页重新发明 |
| **砍掉的功能被发现还在用** | 返工，且是最贵的那种 | MVP 阶段已决定不做埋点复核，**这个风险是明确接受的**。砍掉的代码留在 git 历史里，真要恢复是从旧仓库捞需求、按新范式重做，不是回滚 |
| **工期不确定性** | 重建的估算精度低于翻译 | 阶段 2 结束用真实速率重估 |
| **`ExecutionTimeline` 2,196 行** | 裁剪后最大的单文件，也是交互重做最重的一块 | 单独排 2 周（阶段 4b），契约先行，拆成三个组件 |
| **Nexus / Scout 不同步** | 节点页写功能做不完 | 阶段 0 对齐接口与排期；读写分离交付 |
| **Scout 冷启动能力消失** | 用户失去"一键启动" | 上线前准备好设备侧常驻服务的安装方案与说明 |
| **双前端并行期** | 两套老系统仍要修 bug | 阶段 2 后冻结 Console 新功能；阶段 4 后冻结 Studio |
