# 项目入口与应用配置调整

全局首页 `/testing` 只展示项目，创建按钮统一为“新建项目”。项目即使没有应用也能进入。搜索、最近访问、左侧导航、管理后台入口及命令面板均以项目为单位。

项目工作台地址为 `/testing/projects/<projectId>`。创建成功后进入“配置 → 应用管理”，此处是业务应用的创建入口；首页不再提供“新建应用”或分裂的新建菜单。应用仍保留原 ID 和所属项目，不把已有应用转换成项目，不迁移或删除现有业务记录。

项目配置包含：应用管理、项目环境、控件定位、账号事实、项目维护者。应用管理是唯一的应用创建入口，进入已有应用后统一切换运行环境、开发配置、登录校验。项目环境只管理名称、顺序与默认环境；不再新增另一套渠道或应用。旧 development/login-evidence 链接仍定位对应应用。运行配置以 channel.app_id 关联实际应用，仅展示应用已有平台；同平台多个应用使用独立 channel ID。

用例执行结果、任务、问题与 Session Log 继续按实际目标应用读取。一个项目有多个应用时必须选择目标，不默认替用户选择第一个；唯一应用可以直接使用。目标保存在 URL，刷新可恢复。换目标会清掉旧目标的任务/会话等查询状态；跨项目的应用 ID 不会被接受。

旧 `/testing/<appId>` 链接先读取应用实际所属项目，再跳转到新项目页面并保留目标、任务和会话参数，不信任旧链接传入的 projectId。旧设置和目录链接也接入项目导航。无需修改已有任务、会话或用例数据。

本轮没有发布正式安装包或重启正式服务。页面验证使用隔离 Nexus 数据目录和独立 HTTP 静态服务，截图中的“导航验收项目”“验收 Web”“验收 Mac”为验收数据。

## 验收

真实隔离 Nexus HTTP + 构建后的 Workbench + Chromium（禁缓存、禁 Service Worker）通过：新建项目并进入空项目、项目内新建两个应用、首页只列项目、目标选择和刷新、旧链接按服务端归属纠正、开发/登录配置分别绑定应用、跨项目目标拒绝、项目命令搜索及相关面板懒加载。

86 个打包资源完成 HTTP 加载与 JS/CSS 解析，页面错误、请求失败和本地资源错误均为 0。TypeScript 构建、仓库规则与 ESLint 通过。验收服务已停止，真实业务数据未改。

## 应用配置统一（2026-10-18）

Nexus 保留 channel.app_id 并校验项目归属、平台和同应用平台唯一性。读取时为现有应用生成运行入口投影；只有一个同平台应用且只有一个未关联历史渠道时，复用原渠道 ID 和全部环境参数。新增第二个应用前固化已有唯一关联，避免原配置归属变化。多候选历史配置保留，用户可在应用内显式选择复用；不会删除旧参数。保存仍通过原项目环境存储，不新建平行配置真源。

任务选择只显示目标应用的运行渠道；设备目标解析拒绝其他应用渠道。开发配置与登录校验复用原接口与 app ID。配置编辑保留未保存离页提示。

隔离 HTTP + Chromium 验收：唯一历史配置复用、保存后刷新、其他环境参数保留、同平台多个应用隔离、错误 app_id 写入返回 422、旧开发链接、显式历史复用且原值保留。87 个打包资源加载解析无错误；源码构建和改动文件 ESLint 通过。未发布安装包，未写入真实项目数据。

## 旧接口读取兼容

Workbench 不再把缺少 app_id 的历史渠道过滤为空：优先按明确归属读取；否则展示当前应用平台的未关联历史配置。只有同平台应用和历史配置均唯一时自动选中，其他情况要求显式选择，绝不展示归属于其他应用的配置。兼容读取不补写 app_id、不生成新渠道、不替换原配置键；按原渠道保存参数。任务选择复用相同规则。归属明确后继续按应用隔离。
