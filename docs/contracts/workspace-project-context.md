# 工作区项目上下文与回复归属

## 数据

项目列表沿用 `GET /project/list`；当前项目名称由工作区 options 的 `project` 返回，旧服务使用同一项目列表按 URL projectId 查找。消息正文和回复处理状态仍分别来自工作区 detail 的 `body`、`reply_status`、`reply_error`。

## 状态

项目归属以 URL 中的 projectId 为准；对话 topic、应用和测试渠道不能跨项目沿用。项目名称在对话详情顶部展示，不与测试目标混排。

## 交互

对话详情在成员、测试目标、任务标签前提供项目选择，切换导航到目标项目的工作区列表，不复制、迁移或覆盖原对话，不沿用原项目的 topic、appId、collabCase、环境或渠道。当前项目原有对话仍可返回查看。

用户气泡只展示用户提交的正文。管家处理失败的详细原因属于管家消息；用户消息旁只显示回复处理状态，悬停可查看处理诊断。复制消息仍只复制原正文。

## 边界

项目列表或测试目标读取失败时明确提示，不把其他项目的应用当成兜底。后端拒绝当前工作区之外的项目或应用参数；用户明确提到另一个唯一项目时，说明归属不一致并提供项目入口，不在原项目上继续执行。

重复查询停止仅是内部防循环，不代表用户问题已回答或操作已完成。管家使用已有事实回答当前问题；没有证据的执行、重启或成功不得宣称完成。

## 不做

不修改历史消息正文，不迁移工作区所属项目，不改写业务数据库，不通过 shell 管理用户 IDE 或业务服务进程，不将开发环境检查/重启混为测试用例执行。
