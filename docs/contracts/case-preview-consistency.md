# 用例预览 UI 一致性（强制要求）

用户明确要求：**完整预览直接放在用例列表的对应行内。每条用例都有自己的预览，默认可见，无需先点选某条。**

- 列表行包含用例身份信息及其完整的前置条件、操作步骤、预期结果三栏预览；不同用例不能共用一个随选择变化的预览区域。
- 不得改为左列表右预览，也不得改为上列表下预览。之前两种布局都是对需求的错误理解，已撤销。
- 行内预览与导入预览共用 `CaseReadingView → CaseScriptSections → ScriptField` 及样式。相同原文和解析数据的预览内容必须一致。
- 原文完整展示，保留逐行编号、对应片段后的彩色解析标注、任务顺序、资源准备、待处理提示。不以摘要、截断文本、默认纯原文、折叠行或抽屉代替行内完整预览。
- 抽屉只作为版本、复核等附加操作的入口，不承担默认预览展示。
- 每行解析数据按 case_id 隔离。列表已提供解析时直接复用；缺少时按可见区域补读已保存详情，失败在该行显示原文与重试，未解析则明确提示，不触发重新解析。
- 宽屏每行预览三栏并排；窄屏转卡片后预览仍留在对应卡片内，并完整纵向排列。
- 保留搜索、模块及结果筛选、分页、跨页勾选、批量执行和删除。勾选或取消选择不影响任何行的预览展示。

## 回归验收

构建后运行 `python3 scripts/check-case-preview-ui.py --dist dist --output /tmp/mino-case-ui-check`。需要 Python Playwright 与 Chromium，可用 `--browser /absolute/path/to/chromium` 指定已有浏览器。

验收须断言至少两条用例同时在各自列表行内呈现完整预览，且不存在独立预览面板；比对行内和导入预览 DOM，并覆盖详情失败重试、原文保留、筛选、分页、批量勾选与窄屏卡片。测试只使用模拟 API，不写入真实业务数据。


## 导入入口

点击“导入用例”每次直接打开新建导入的“选择来源”页面，包括曾关闭过解析预览或结果页的情况。恢复记录不得替换或阻塞新建界面；恢复旧任务只作为来源选择下方的可选操作。新任务按独立身份保存恢复记录，兼容旧单记录格式；新建、关闭、返回列表不会清除其他任务的记录。恢复解析只读取旧 token，恢复提交只查询原 requestId，不自动重复解析或提交。记录仍按账号、项目隔离并在 24 小时后不再展示。
