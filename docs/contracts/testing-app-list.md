# 行为契约 · 应用列表

**原始实现**：`MinoStudio/src/views/Testing/AppList.vue` 357 行
**目标路由**：`/testing`
**排期**：阶段 2（P0 链路入口）
**状态**：**已实现**

## 数据

| 来源 | 用途 | 形状 |
|---|---|---|
| `GET /project/list` | 项目 + 其下应用 | `{data: Project[]}`，`Project.apps: App[]` |
| `GET /case-runner/tasks/summary?app_ids=` | 每个应用的运行中计数、最近一次任务 | `{data: {items: Row[]}}` 或 `{data: Row[]}` |
| `GET /case-runner/runs?limit=40` | summary 不可用时的兜底 | `{data: {runs: Run[]}}` |

**形状说明**：这三个接口需要登录，本次未能对活体验证，形状是**从原 Vue 代码的消费逻辑反推**的。原实现对每个接口都做了双形状兜底（`Array.isArray(res) ? res : res?.data`、`s?.data?.items || s?.data`），说明历史上返回体变过。重建保留同样的兜底，并在类型里标注。

**summary 失败时降级到 runs** 是原实现的既有行为（`isMissingTaskEndpoint` 判断接口不存在就静默兜底），保留——老 Nexus 没有 summary 接口。

## 边界

- **完全没有项目**：引导去新建项目，而不是只显示"暂无数据"。
- **项目下没有应用**：该项目区块显示「这个项目还没有应用」+ 新建入口。
- 加载态：骨架卡片，不整页转圈。
- **`/project/list` 失败**：整页错误态 + 重试按钮，并提示检查 Nexus。
- **summary / runs 都失败**：列表正常显示，只是没有任务角标——**计数是增强信息，不该拖垮主列表**。
- 搜索无结果：空态提示换个关键字，保留搜索框内容。
- 超长应用名 / 项目名：卡片内省略号，悬浮看全文。
- `platforms` 字段可能是逗号字符串也可能是数组：由 `constants/appPlatforms` 归一。

## 不做

- 原实现的 `enterDefaultProject()`：进页自动跳进第一个项目（或 `?projectId=` 指定的项目）→ **不做**。自动跳转让用户没法看到项目全貌，也让浏览器返回键行为变怪。改为显示全部项目，用户自己点。
- 原实现的 `?task=` 直达某任务的 query 消费（`consumeTaskQuery`）→ **不做**，任务详情由 `/testing/:appId?tab=tasks` 自己处理，列表页不承担路由中转。
- 不做删除项目 / 删除应用 → 本期不做，走管理后台（已推迟）。
